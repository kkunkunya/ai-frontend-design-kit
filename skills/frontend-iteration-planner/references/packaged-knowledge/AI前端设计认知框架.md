# AI 前端设计认知框架

## 一句话

AI ==不负责替我形成审美判断==；AI 负责在我==给定的判断边界内，快速探索、实现、回看、迭代==。

所以新项目前端设计的起点，不是先生成页面，而是==先生成约束==。

## 2026-04-21 重大重构说明

本框架从"七层框架"演化为"**阶段化流程 + 横切机制 + 上位骨架**"的三维组合：

- **上位骨架**：[[六维：形色字构质动是网站试吃的机械骨架]] 作为调研/试吃的机械维度
- **横切机制**：[[深度采访双轮：产品设计师视角的横切机制]] 贯穿需求和定稿两个节点
- **生成层重构**：从"AI 生成 2-4 方案选一个"改为"视觉锚定三件套前移探索"——详见 [[视觉锚定三件套：代价结构与资产生成双路径]]
- **动效文档双层化**：[[动效文档两层：MOTION-SPEC vs 实现 prompt 集]] 把动效采访的产出分宏观（给人读）和微观（喂 Agent）两层

旧"七层框架"的知识没有被否定，而是被**重新组织进新阶段流程**。详细差异见文末"2026-04-21 重构来源"段。

## 第零原则：先定主语言

在所有阶段之前，有一个==比 visual thesis 更上游的东西==：**主语言**。

主语言是贯穿产品==所有表达通道==（字体、布局、动效、背景、间距、颜色、文案、细节）的==单一叙事逻辑==。它不是形容词（"高级"、"极客"），是动词（"滚动时混沌收敛为有序"）。

没有主语言的项目，每个 section 都能过关但合起来像拼贴。有主语言的项目，每个决策都能被一条线索解释。

开工第一天必须能回答 5 个问题：

1. 这个网站在讲什么故事？
2. 用户从打开到离开经历了什么时间维度的变化？
3. 动效 / 字体 / 布局 / 背景 / 颜色 / 文案 / 细节 / 交互 各承载什么角色？
4. 为了清晰，主动放弃了哪些好看但偏离的东西？
5. 哪个已有作品体现了类似的主语言？

回答不出来就别开工。详见 [[主语言是设计的第一原则]]。

主语言和六维是姊妹机制：==主语言是整合器（定义自己），六维是拆解器（分析别人）==。

## 我现在看到的根因

过去做 AI 前端时，问题往往不是"模型不够强"，而是：

- ==设计方向没有先收敛==，生成过程很随机
- 生成后主要靠很多次微调，==没有稳定的评审标准==
- 前端探索和后端契约经常脱节
- AI 可以很快产出内容，但我缺少一套判断什么算好的流程
- **老版"生成 2-4 方向选一个"在代码层探索太昂贵**——用户看半成品页面脑补成本高，Agent 写多个变体散失方向感

真正缺的是一个完整的前端设计工作流，其中探索和约束都要前置到图像层。

## 三种项目场景（先判型再走流程）

一个项目不是只有"从零开始"这一种状态，==实际工作中三种场景都会遇到==：

| 场景 | 触发 | 走什么 |
|---|---|---|
| **A 全新项目** | 没有 `knowledge/design-docs/design.md` 或只有空骨架 | 下方"新阶段化流程"**完整阶段 1-7** |
| **B 整站视觉重写** | design.md 存在但用户明确要**换主 Moodboard 方向 / 换主语言** | **回阶段 2-4 重跑**（六维 + 后轮 + 视觉锚定三件套重生） |
| **C 二开 / 增量** | design.md 定稿（`stage: 3-finalized` 或等价）+ 加新页面 / 新 section / 微改 | ★ `frontend-iteration-planner` 入口路由——读老资产 + 三档 tier 裁剪（T1 新页面 / T2 新 section / T3 微改） |

本框架的主干（"新阶段化流程"段）默认描述**场景 A**的完整施工流程。场景 B 是主干的一段重跑；场景 C 是==另一条独立裁剪路径==，核心思路是"老 design.md 是资产不是债务"——硬前置读取 + 按档裁剪，不重走主干。

场景 C 的完整方法论见 [[场景 C 二开：老资产保护与三档 tier 裁剪]]：为什么要单独讨论、硬前置三件套、三档 tier 的边界、跨档处理、§15 迭代日志。

硬分流原则：
- 判断顺序——先看 design.md 是否存在且 §0 主语言是动词句式 → 是则进 B 或 C → 再看用户意图是"换方向"还是"加东西"
- ==禁止== 模型假装是新项目（看到任务就从零出 token / moodboard / 动效）——这是场景 C 最大的雷
- 跨档任务（T1 加页面 + T3 改主色）拆成多次执行，不合并
- T3 滑向 T2（改着改着超出单 token / 单组件 / 单参数范围）立即回步骤 1 重判

## 新阶段化流程（2026-04-21 版）

整个前端设计流程分 7 个阶段，从需求到迭代单线推进，==只在 Moodboard 阶段做分支探索==：

```
┌─ 阶段 1：需求定义（开工三件套 + 前轮深度采访）
│  整体风格 + 页面框架 + 文案内容 → 主语言 + 目标
└──
   ↓
┌─ 阶段 2：试吃（六维机械拆解 × 4-5 站）
│  一次一站保护上下文 → 综合成【一份本项目的 design.md 初稿】
└──
   ↓
┌─ 阶段 3：后轮深度采访（产品设计师视角）
│  结合 Moodboard 参考 → 补齐架构 + 文案细节 → design.md 定稿
└──
   ↓
┌─ 阶段 4：视觉锚定三件套（生成图像，不生成代码）
│  A. Moodboard Prompt（★ 前移探索：2-3 张让用户选 ★）
│  B. 完整网页示意图 Prompt（主页 → 子页/下滑）
│  C. 动效双产出：帧序列示意图 + 动效实现 prompt 文档
└──
   ↓
┌─ 阶段 5：资产生成（双路径）
│  主路径：baoyu-imagine skill 自动生成图/视频
│  兜底：失败时打开 prompt 文件让用户手动复制到网页端
└──
   ↓
┌─ 阶段 6：代码实现（基于所有视觉锚点 + design.md + 动效 prompt）
│  Pre-flight 外显化 → 单线生成 → 完整性验收
└──
   ↓
┌─ 阶段 7：迭代微调（反馈驱动）
│  审美追问三段式 + 参数外显 Tweaks + 修正反写回 design.md
└──
```

### 横切机制（贯穿所有阶段）

| 横切 | 触发 | 对应笔记 |
|---|---|---|
| **反 slop 硬禁令** | 每次生成前自动过一遍 | [[反 slop 硬禁令：AI 前端的十条视觉红线]] |
| **完整性验收** | 代码实现阶段交付前 | [[AI 偷懒是训练产物，完整性验收是补偿机制]] |
| **深度采访双轮** | 阶段 1 前轮 + 阶段 3 后轮 | [[深度采访双轮：产品设计师视角的横切机制]] |

## 阶段详解

### 阶段 1：需求定义 + 前轮深度采访

先定义产品任务：

- **整体风格**：想要什么气质 / 不想变成什么
- **页面框架**：站点架构 / 页面数量 / 信息组织
- **文案内容**：调性 / 关键信息 / 叙事线索

触发 [[深度采访双轮：产品设计师视角的横切机制]] 的==前轮==——五类引导式提问（定位 / 用户 / 反向 / 资源 / 时间）建立产品边界。

输出：主语言 + 目标层（写进 `design.md` §0-1）。

### 阶段 2：试吃六维 × 4-5 站

调研参考站时使用 [[六维：形色字构质动是网站试吃的机械骨架]] 作为机械骨架：

1. 根据主语言 + 目标写搜索提示词
2. 找 4-5 个该领域设计优秀的真实网站
3. 一次一站，每站跑一次六维：
   - **形**：图标族 / border-radius / 分割线
   - **色**：DOM 量化色板 + 明暗配比
   - **字**：type scale + 字体族
   - **构**：grid / spacing / 稠密度
   - **质**：材质 / 噪点 / 渐变 / 阴影
   - **动**：按动效采访 5 类（节奏/触发/双向/层级/反例）提问
4. 综合输出：**一份本项目的 design.md 初稿**（不是每站一份，保护上下文）

每维的具体量化落地走 [[从参考案例复刻高级感：量化工作流]]，动效维的采访细则走 [[AI 前端动效盲区与采访补偿]]。

### 阶段 3：后轮深度采访

阶段 2 完成 + Moodboard 生成但未选定之间，触发 [[深度采访双轮：产品设计师视角的横切机制]] 的==后轮==——五类问题（架构 / section / 文案调性 / 交互路径 / 反向细节）拔齐细节。

输出：`design.md` 定稿。

### 阶段 4：视觉锚定三件套

详见 [[视觉锚定三件套：代价结构与资产生成双路径]]。

- **A. Moodboard Prompt**：==前移探索在这里发生==，生成 2-3 张风格不同的 moodboard 让用户选
- **B. 完整网页示意图 Prompt**：选定 Moodboard 后单线，先主页→OK→再子页
- **C. 动效双产出**：帧序列示意图（视觉锚点）+ 动效实现 prompt 文档（代码级规格），按 [[动效文档两层：MOTION-SPEC vs 实现 prompt 集]] 的结构

### 阶段 5：资产生成（双路径）

主路径 `baoyu-imagine` skill 自动调用 GPT Image 2 等模型；失败时打开 prompt 文件由用户手动复制到网页端生成。所有图片 / 视频资产按需生成，归档到项目 `knowledge/references/` 或 `knowledge/design-docs/assets/`。

### 阶段 6：代码实现

#### Pre-flight：系统外显化（落笔前必做）

调研 / 深度采访 / 三件套全部完成后，==在生成第一行代码之前==，Agent 必须**先把将要用的系统用一段话说出来**：

- 本次用的 layout 系统（grid / section 排版 / 稠密度）
- 本次用的调色（基础中性色 + 重音色，取自哪份 token）
- 本次用的字体（主副字体家族 + 字号阶梯）
- 本次用的动效节奏（来自动效实现 prompt 文档的哪几条）
- 本次==放弃==的：为了主语言清晰，哪些默认选项本轮不会出现

为什么是独立动作：不外显化时，Agent 会在"按 design.md 做"和"训练数据默认"之间来回摇摆，生成结果带着隐藏假设；外显化一次后，后续每段代码都可以被这段话对齐检查。借鉴自 Anthropic Design 的 "vocalize the system you will use"。

#### 生成（单线执行，不再多方案探索）

阶段 4 的 Moodboard 选定已完成探索，代码层单线生成：

1. Pre-flight 外显化
2. Agent 读 design.md + 三件套图像 + 动效实现 prompt → 生成代码
3. 反 slop 门禁常驻
4. 完整性验收（禁用模式扫描 + 三步验证 + 断点协议）

==明确废弃"AI 生成 2-4 方案让用户选"==——探索已前移到 Moodboard 阶段，代码阶段是确定性执行。

### 阶段 7：迭代微调

代码生成后，用户看具体页面涌现审美反馈时：

- **判断外显**：用 [[审美是隐性认知，追问是唯一的解压工具]] 的三段式追问（定位 / 对标 / 量化）翻译"感觉不对"
- **参数外显**：用 [[参数外显与判断外显：评审的两条姊妹机制]] 的 Tweaks 协议做可调旋钮
- **反写回 design.md**：所有修正==必须反向写回 design.md==，下次 session 不丢失

## 新项目最小资产六件套（2026-04-21 扩展）

从老版四件套扩展为六件套：

### 1. Product Brief
说明用户、场景、成功信号、non-goals。

### 2. Design Context（三份）

- **2a. `DESIGN-LANGUAGE.md`**（给人读，低频）：target audience / use cases / brand personality / **主语言** / visual thesis / anchor references
- **2b. `design.md`**（给 Agent 读，高频，kun 版扩展到 15 段）：基础 12 段 + 三件套 prompt 引用段（见 [[DESIGN.md 写作与分发手册]]）
- **2c. `MOTION-SPEC.md`**（人 + Agent 并读，中频）：宏观动效清单（见 [[动效文档两层：MOTION-SPEC vs 实现 prompt 集]]）

### 3. 视觉锚定三件套产出物（2026-04-21 新增）

- Moodboard 最终选定版（1 张）
- 完整网页示意图（主页 + 所有子页）
- 动效帧序列图集（每个核心动效 1 套）

### 4. 动效实现 prompt 集（2026-04-21 新增）

每个核心动效组件一份 markdown，按 LoadingScreen 范式写（见 [[动效文档两层：MOTION-SPEC vs 实现 prompt 集]]），住在 `knowledge/design-docs/motion-prompts/`。

### 5. Screen Contract

前后端不脱节的关键。每个关键页面写清：目标 / 主动作 / 必要数据 / 状态集合 / 依赖的 API / 哪些是探索版本。

### 6. Experiment Log

记录探索过的方向、为什么舍弃、最终选了什么。Moodboard 阶段的分支选择必须进这份日志。

## 约束来源的二元性

==约束先于生成==的原则里，有两种性质不同的约束：

| 约束类型 | 来源 | 触发条件 | 过期条件 | 对应机制 |
|---|---|---|---|---|
| **作者硬判断**（不变量） | 作者对"AI 默认输出"的反向观察 | 每个前端项目都触发 | 训练语料分布变化时 | [[反 slop 硬禁令：AI 前端的十条视觉红线]] |
| **项目软诉求**（变量） | 用户对"这个项目"的主语言采访 | 项目启动或改造时 | 项目改方向或收尾时 | [[主语言是设计的第一原则]] + 设计契约 |

两者正交——==硬判断打底 + 软诉求定制==。反 slop 是"米其林总厨的规矩"——不允许用味精；主语言采访是"这桌客人的口味访谈"——今天想吃酸一点。

## 两类项目前端的区别

### 品牌型 / 展示型

如 landing page、官网、营销页。走**完整阶段 1-7**。重点在：第一屏构图 / 品牌识别 / 图像与氛围 / 叙事推进 / CTA 转化。

### 工具型 / 应用型

如 dashboard、agent 产品、工作台、管理台。==简化版流程==：

- 阶段 1-3（需求 + 试吃六维 + 深度采访）全走
- 阶段 4 三件套**只做 A 和 B**，跳过 C 动效帧序列
- 阶段 5 资产生成按需
- 阶段 6-7 正常走

重点在：信息层级 / 状态可见性 / 操作路径 / 文案清晰度 / 真实数据与 edge cases。Screen Contract 比 Design Context 更重要。

## 人脑层 / 项目层 / 系统层 / Skill 层分工

### 人脑层
保留判断框架：什么算方向对 / 什么算结果好 / 什么是假高级 / 什么值得保留。

### 项目文档层
上下文和契约：Product Brief / Design Context（三份）/ 视觉锚定产出 / 动效实现 prompt / Screen Contract / Experiment Log。

### shared prompt core 层
轻量的前端设计剧本，不塞审美口号。

### Skill 层
规则 / 触发边界 / 模式路由 / 具体操作。frontend-suite 下的各 skill 按阶段分工。
