# 视觉锚定三件套：代价结构与资产生成双路径

## 一句话

==在写第一行代码之前==，先用三个图像级锚点把视觉方向钉死——**Moodboard（风格板）→ 完整网页示意图 → 动效帧序列**。把"探索"从代码层前移到图像层，用 AI 生图的便宜换 AI 写代码的昂贵。

## 为什么要前移探索

旧流程"生成层出 2-4 个探索方案让用户选"有两个结构性缺陷：

1. **代码层探索昂贵**——每个方案都要半实现才能看出来，Agent 容易在细节上投入算力却散失方向感
2. **用户看代码反馈慢**——用户看一个半成品页面需要脑补大量空白，反馈周期长，且无法判断真实视觉效果

前移探索的核心赌局：==AI 生图便宜（分钟级）+ 视觉传达直接（所见即所得）==，所以把"探索"推到图像锚定层，代码层做单线执行。

## 三件套定义

| 锚点 | 图像形态 | 凝聚维度 | 典型参考 |
|---|---|---|---|
| **A. Moodboard** | 一张综合风格板（色板 + 材质样本 + 符号族 + 字体 + UI 片段） | 六维的静态 5 维（形/色/字/构/质） | CIVITAS Renascentia 风格板、Dribbble moodboard 风格 |
| **B. 完整网页示意图** | 主页 → 子页/下滑的完整页面示意图 | 真实页面布局 + 信息层级 + 叙事推进 | Figma 高保真稿 / midjourney 网页 mock |
| **C. 动效帧序列** | 从左到右的帧变化示例（静态图拼接） | 六维的动维 | Principle / Figma smart animate 帧导出 |

## 为什么是"三件"

三件套对应**静态 + 结构 + 时间**三层视觉锚定：

- **A Moodboard 管"气质"**——这个产品看起来是什么气质，六维静态 5 维的凝聚
- **B 示意图管"空间"**——具体页面长什么样，section 怎么排、信息怎么分层、叙事怎么推进
- **C 帧序列管"时间"**——核心动效怎么变化，截图传不了时间维度，必须单独做

缺任何一件，AI 在代码层都会瞎猜：没 A 会走向默认 SaaS 风；没 B 会走向标准 landing 八股；没 C 会走向 `fade-in` 通用套路。

## 前移探索的位置

旧的"探索 2-4 方案"并没有消失，而是**前移到 Moodboard 阶段**：

```
试吃综合 + 深度采访 → design.md 定稿
          ↓
   ┌─ Moodboard Prompt（生成 2-3 张风格不同的 moodboard）
   │                ↓
   │        用户选定一张 → 后续单线
   │                ↓
   ├─ 完整网页示意图 Prompt（主页 → 满意 → 子页）
   │                ↓
   └─ 动效帧序列 Prompt（核心动效逐一帧序列化）
```

==只在阶段 A 做分支探索==，阶段 B / C 是单线执行——因为阶段 A 选定后方向已钉死。

## 资产生成双路径

三件套的所有产出都是**通过 prompt 调用图像生成模型**，不是手绘/手设计。执行路径分主兜底：

| 路径 | 触发 | 执行方式 |
|---|---|---|
| **主路径** | 默认 | 调用 `baoyu-imagine` skill，用 GPT Image 2（或对应可用模型）自动生成 |
| **兜底路径** | 主路径失败（API 限额/内容安全拒绝/模型不可用） | Agent 告知用户 + 打开生成的 prompt 文件，由用户复制到网页端模型手动生成 |

==双路径的意义==：保证流程不会因为 API 临时问题卡死，但不强制用户手动——主路径能跑就主路径跑。

## 每个锚点的 prompt 结构

### A. Moodboard prompt 结构

核心要素（以 CIVITAS 为范式）：

1. **主概念**（一句话主语言）
2. **必含元素清单**：色板 swatches、材质样本、符号族、字体样本、UI 片段
3. **色彩方向**：具体颜色名或 hex
4. **氛围关键词**：5-8 个形容词
5. **反例清单**（avoid）：明确不要的风格
6. **composition 约束**：不是网页截图，是编辑排版风格的设计板

### B. 完整网页示意图 prompt 结构

核心要素：

1. **页面类型**（landing / hero / feature / product 等）
2. **主叙事**（从上到下讲什么故事）
3. **section 分解**：每个 section 的目标 + 主元素 + 视觉层级
4. **调色 / 字体 / 材质**（从选定的 Moodboard 复制过来）
5. **真实文案占位**（不是 lorem ipsum，是产品级 placeholder）

### C. 动效帧序列 prompt 结构

核心要素：

1. **动效目标**（Loading / Hero 入场 / scroll-driven 等）
2. **起始帧、中间关键帧、终止帧**的逐一视觉描述
3. **时长 + 缓动曲线**（作为帧间过渡的隐性约束）
4. **触发条件**（scroll 到哪个点 / hover / 点击）

帧序列图是**视觉锚点**，不是实现规格——实现规格要走 [[动效文档两层：MOTION-SPEC vs 实现 prompt 集]] 的微观层另写。

## 样板不存在笔记库

==笔记库（Obsidian）只存方法论==——"moodboard prompt 应该长什么样"的结构定义。

具体样板（CIVITAS 那张图的完整 prompt / LoadingScreen 的完整规格）**住在具体项目的 `knowledge/design-docs/` 或 `knowledge/references/` 里**，按项目 context 生成，用完归档。这是 harness programming 的缰绳约束层，不是认知方法论。

Agent 的行为规范：进入一个项目做三件套时，==现场根据本项目的 design.md 生成样板==，不跨项目复用样板。

## 和 DESIGN.md 的关系

三件套不替代 `design.md`——`design.md` 是==文字版约束===（给 Agent 读的规格），三件套是==图像版锚点==（给人 + Agent 共读的视觉参照）。

```
design.md（文字约束）
   ||
   ++--- Moodboard（风格锚点）
   |
   ++--- 示意图（空间锚点）
   |
   ++--- 动效帧序列（时间锚点）
          |
          ++--- 动效实现 prompt（代码级规格）
```

代码生成时 Agent 同时读 design.md + 三件套图像 → 生成网页 → 用户反馈 → 迭代。

## 和老"变体探索光谱"的关系

老笔记 [[AI前端设计认知框架]] §4 生成层的"变体探索光谱（by-the-book / 中间带 / Novel）"被==前移吸收==：

- 探索光谱的**意图**（让用户看到不同可能性）仍然成立
- 探索光谱的**执行层**从"代码变体"改成"moodboard 变体"
- 光谱的"规整 vs 新颖"两端对应 moodboard 的"保守配色 vs 实验材质"

不冲突，只是前移到图像层。

## deletion-spec

- **触发删除条件**：当 AI 生图成本显著上升（比如模型 API 定价变化）使得"前移探索"的代价优势消失，或者 AI 代码生成达到一次通过的稳定度（不需要视觉锚定就能生成正确），本三件套可降级。若三件套缩减为两件（比如帧序列被动效文档吸收）或扩展为四件（增加比如"信息架构图"），需重写。
