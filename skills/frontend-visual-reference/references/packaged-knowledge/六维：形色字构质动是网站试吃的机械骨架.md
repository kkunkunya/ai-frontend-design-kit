# 六维：形色字构质动是网站试吃的机械骨架

## 一句话

==形、色、字、构、质、动==是把"感觉高级"==机械化成可量化、可追问的六个维度==，是 AI 试吃参考网站的上位骨架——所有具体量化工作流（DOM 量化、动效采访、三段式追问）都挂到这六维上落地。

## 为什么需要上位骨架

AI 试吃参考站常见两种失败：

1. **偷懒只抄色板**——抄了配色但字体、布局、材质、动效全走样，理由是"色彩最容易观察"
2. **感觉驱动无章可循**——"感觉很高级"但说不清楚哪里高级，回到生成层仍然复刻不出来

两种失败的根源都是==没有机械化的拆解维度==，审美判断在头脑里是整体性的，但要复刻必须**拆成并列的正交维度**逐一观察 + 记录。

## 六维定义

| 维 | 内涵 | 可测量/可追问 | 菜肴比喻 |
|---|---|---|---|
| **形** | 元素轮廓与几何倾向——锐角/圆角、直线/曲线、对称/偏置、几何/有机 | `border-radius` / `clip-path` / SVG 路径 / 图标族风格 | 菜的**造型**（摆盘） |
| **色** | 色板层级——基础中性 + 主色 + 重音色 + 饱和度分布 + 明暗对比度 | token 系统 / `color` / `background` / 明暗配比 | 菜的**颜色** |
| **字** | 字体族 + 字号阶梯 + 行高 + 字距 + 粗细分布 + 衬线/无衬线 | `font-family` / type scale / `letter-spacing` | 菜单**排版**（信息秩序） |
| **构** | 骨架——栅格、留白、比例、节拍、稠密度、section 排版 | grid / spacing token / 容器宽度 | 盘子的**构图**（松/紧） |
| **质** | 材质感——光面/磨砂/纸质/金属/噪点/透明/渐变/阴影 | `backdrop-filter` / noise / shadow / gradient | 菜的**质地**（口感） |
| **动** | 时间维度——触发/缓动/时长/分步/双向性/stagger | transition / keyframes / framer / scroll-linked | 上菜的**节奏** |

## 为什么正好是六维

不是更多，也不是更少，有三条经验判断：

**1. 覆盖全**——静态 5 维 + 动态 1 维。静态里，形/色/字是**元素级**（一个 button 长什么样），构是**布局级**（elements 怎么排），质是**氛围级**（整体材质基调）。三级静态 + 时间动态，覆盖网站的所有可感知层。

**2. 每维可量化**——每一维都对应具体的 DOM / CSS 参数层，不依赖"感觉"。可量化是上位骨架能收敛 AI 偷懒输出的前提。

**3. 每维正交**——色和字可以独立变化（同色板可换字体）、构和质可以独立变化（同栅格可换材质）。正交意味着采访和复刻时==可以逐维推进==而不混淆。

## 六维 vs 主语言：拆解器 vs 整合器

| 角色 | 机制 | 使用阶段 |
|---|---|---|
| **六维是拆解器** | 把参考站拆成 6 份独立观察 | 调研/试吃阶段——**分析别人** |
| **主语言是整合器** | 贯穿六维的单一叙事逻辑 | 生成/落地阶段——**定义自己** |

两者互补，不冲突：

- 试吃别人时用==六维==：看 Linear、看 Stripe、看 Anthropic Design，分别在六维上记录参数
- 做自己时用==主语言==：一句话主叙事贯穿六维，让所有维度指向同一个故事（"滚动时混沌收敛为有序"这类动词）

==误区==：拿六维去定义自己的产品——会得到一个四平八稳的合格品，但没有灵魂。主语言这一层不能跳。

## 六维作为上位骨架：现有 checklist 怎么挂

六维**不替代**现有的 DOM 量化 / 动效采访 / 三段式追问等具体方法论——它是骨架，现有方法论是肌肉：

| 六维 | 落地手段 | 对应现有笔记 |
|---|---|---|
| **形** | 图标族盘点 + SVG 路径采样 + `border-radius` token 表 | [[从参考案例复刻高级感：量化工作流]] |
| **色** | DOM 量化 5 步法 + Coolors 对比 + token 导出 | [[从参考案例复刻高级感：量化工作流]] |
| **字** | DOM 量化 5 步法（字号/行高/字距） | [[从参考案例复刻高级感：量化工作流]] |
| **构** | DOM 量化 5 步法（spacing/grid/宽度）+ 截图栅格标注 | [[从参考案例复刻高级感：量化工作流]] |
| **质** | 背景层采样 + noise 密度 + 阴影量化 | DOM 量化补全 |
| **动** | 动效采访 5 类问题 + 量化语法 + 动效文档两层 | [[AI 前端动效盲区与采访补偿]] · [[动效文档两层：MOTION-SPEC vs 实现 prompt 集]] |

骨架稳定不变，肌肉可以持续增补。新发现一个量化手段，就挂到对应维下，不改骨架。

## 和 CIVITAS moodboard 的完美对齐

用户在 2026-04-21 提到的 CIVITAS Renascentia 品牌 moodboard（Renaissance 主题、web3 文化资产协议）在一张静态图里凝聚了五维：

| moodboard 区块 | 对应维 |
|---|---|
| Color Palette（色板 + 配色示例） | **色** |
| Material Exploration（材质样本） | **质** |
| Typography（字体家族 + 字号阶梯） | **字** |
| Visual Language（视觉语言）+ Symbols & Signifiers（符号族） | **形** |
| UI Language Fragments（栅格 + 间距 + 信息层级） | **构** |
| *（缺）* | **动**——必须单独做帧序列 |

==这正是"视觉锚定三件套"的由来==：一张 moodboard 能凝聚静态五维，动效必须单独做**帧序列图 + 实现 prompt 文档**。详见 [[视觉锚定三件套：代价结构与资产生成双路径]]。

## 一次完整试吃的六维流程

以试吃 Linear 为例（展示型流程）：

1. **形**：截屏标注——按钮圆角、图标族风格、分割线、装饰符号；输出：一张标注图 + `border-radius` 表
2. **色**：DOM 量化——主色 / 中性 / 重音色 + 明暗配比；输出：color token 表 + 明暗饱和度分布图
3. **字**：DOM 量化——字体族 + 字号阶梯 + 行高；输出：type scale 表
4. **构**：截图栅格标注——section 宽度、垂直间距、稠密度；输出：栅格线截图 + spacing token 表
5. **质**：背景层采样 + 阴影/渐变列表；输出：material 表
6. **动**：滚动 + hover + 点击，按 [[AI 前端动效盲区与采访补偿]] 的 5 类问题采访；输出：量化语法清单 + 双向性约定

==一次一站==：四五个参考站不一次吃完，上下文会挤垮。每站跑一次六维，最后综合成**一份**本项目的 `design.md`。

## 六维和 7-step 流程的位置

在 [[AI前端设计认知框架]] 的阶段化流程里，六维位于==试吃阶段==：

```
需求三件套 → [试吃阶段：六维拆解 × 4-5 站 → 综合] → 深度采访双轮 → ...
```

六维是试吃的方法论骨架，综合阶段把六维观察压缩进 `design.md`。

## 常见误区

- ==不要把六维当权重评分表==：不是给每站打 6 维分数选最高的，六维是**观察维度**，不是评价维度
- ==不要每维都穷尽==：每维记录"和本项目主语言最相关的部分"即可，完整测量留给 DOM 量化工作流按需做
- ==不要跳过"质"这一维==：质是最容易被忽略也最容易出 AI 味的一维（默认渲染质感扁平、无材质）

## deletion-spec

- **触发删除条件**：当 AI 试吃参考站默认就能稳定覆盖六维（不偷懒只抄色板、不忽略材质和动效）时，本骨架可降级为剧本层提醒或整体退场。若未来六维有拆分（比如"形"拆成"形状"+"图标族"）或合并（比如"字+构"合并），需重写整篇。
