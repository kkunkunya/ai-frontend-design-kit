# 主语言是设计的第一原则

## 一句话

**主语言**是贯穿一个产品==所有表达通道==（字体、布局、动效、背景、间距、颜色、文案、细节）的==单一叙事逻辑==。主语言是设计的第一原则，==比 visual thesis 更高一层，也更难==，必须在项目第一天定下来。没有主语言的前端，本质上是一堆 section 各自好看的拼贴。

## 主语言 ≠ visual thesis

| | visual thesis | 主语言 |
|---|---|---|
| 形式 | 一句话描述视觉气质 | 贯穿全站的叙事逻辑 |
| 例子 | "机构级可信度 × 极客 Builder 精神" | "scroll-driven chaos → order：Web3 项目从混乱探索到协同成型" |
| 范围 | 气质标签 | 叙事动线 + 表达通道规则 |
| 落地方式 | 写进 Design Context | 每个动效 / 字体 / 布局决策都要被它解释 |
| 缺席代价 | 页面看起来模糊但不致命 | 每个 section 各自好看但不连贯 |

==visual thesis 是形容词，主语言是动词==。visual thesis 告诉你"气质是什么"，主语言告诉你"故事是怎么推进的、每个元素在故事里扮演什么角色"。

## 主语言 vs 六维：整合器 vs 拆解器

主语言和 [[六维：形色字构质动是网站试吃的机械骨架]] 是一对姊妹机制，服务不同阶段：

| 角色 | 机制 | 使用阶段 | 服务对象 |
|---|---|---|---|
| **拆解器** | 六维把参考站拆成 6 份独立观察 | 调研/试吃阶段 | **分析别人** |
| **整合器** | 主语言用单一叙事逻辑贯穿六维 | 生成/落地阶段 | **定义自己** |

两者不冲突：

- 试吃别人时==先用六维==（机械拆解，避免只抄色板），从 4-5 个参考站各提取六维观察
- 做自己时==回到主语言==（整合收敛），让所有维度指向同一个故事，而不是把六维观察平均掉

==误区==：拿六维去定义自己的产品——会得到四平八稳的合格品，但没有灵魂。六维只管"如何精确观察别人"，主语言管"如何有灵魂地做自己"。

## 为什么主语言是第一原则

没有主语言的项目通常长这样：

- Hero 很酷（有某种风格）
- About 段很干净（有另一种风格）
- Features grid 很现代（有第三种风格）
- 单独看每一块都不错
- **合起来像拼贴**

这不是执行问题，是==没有一条贯穿的线索==。每个 section 的设计师都在各自发挥，没有主语言来统一约束。

有主语言的项目：

- 每个动效都在服务同一个叙事
- 每个字体都在强化同一个气质
- 每个间距都有同样的节奏
- **合起来像一个东西在生长**

Dragonfly 之所以被反复参考，不是因为它某一个元素做得好，而是因为它有非常清晰的主语言：==ASCII 粒子地图 + 橙红点缀 + serif 机构感字体 + 缓慢滚动== 这四个东西一起讲"全球化加密基础设施"这个故事。每个元素都在为这个故事服务。

## 主语言的表达通道

主语言不是一个东西，是一条==穿过所有表达通道的叙事线==。典型通道：

### 1. 动效通道

- 主叙事的时间维度：什么先发生 / 什么后发生 / 怎么变化
- 本项目例子：scroll-driven chaos→order 的 5 维度演化

### 2. 字体通道

- 字体选择 / 字重 / 字号层级 / letter-spacing
- 本项目例子：Space Grotesk Light 300 (品牌名) + Cormorant Garamond Light 300 (正文 serif) + JetBrains Mono (标签) —— 三字体策略表达"机构 × 极客"

### 3. 布局通道

- 容器宽度 / 栅格 / 对齐规则 / 错位关系
- 本项目例子：段落错位布局（Para1 左 55% + Para2 右 60%）像书籍正文，表达"认真做事的创业者"而非"VC fund"

### 4. 颜色通道

- 主色 + 背景 + 层级 + 对比度
- 本项目例子：纯黑 #000 + 橙红 #FA4C14 + 灰白 #F2F2F2 —— 同色系克制，只用颜色差异化主次而非装饰

### 5. 背景通道

- 背景是被动的还是参与叙事的
- 本项目例子：ASCII 网络拓扑，从顶部混沌字符场 → 滚到底部变成清晰网络结构。==背景在讲 Web3 项目如何被"搭"出来==

### 6. 文案通道

- 语气 / 长度 / 标点 / 术语密度
- 本项目例子：禁止 marketing 味（"赋能"、"生态"），用 builder 语言（"we ship product, not pitch decks"）

### 7. 细节通道

- 四角品牌字母 / 图标像素风 / 分隔线 / 滚动指示器
- 本项目例子：四角 F O R G E serif 衬线字母 0.1 opacity，和 Dragonfly 的 D R L Y 同构

### 8. 交互通道

- hover 反馈 / 光标 / 状态切换 / 数据加载
- 本项目例子：hover 节点时触发节点 + 连线橙色高亮，强化"点击即看到连接"的主叙事

## 一个好主语言的 5 个验证问题

项目开工前必须能回答这 5 个问题。回答不出来就是没有主语言：

1. **一句话主叙事**：这个网站在讲一个什么故事？（不是卖什么，是"展开一个什么叙事"）
2. **时间维度**：用户从打开到离开，视觉和叙事上经历了什么变化？
3. **每个通道各承载什么**：动效 / 字体 / 布局 / 背景 各自在故事里扮演什么角色？
4. **不做什么**：为了保持这个故事清晰，==主动放弃==了哪些好看但偏离的东西？
5. **参考锚点**：哪个已有作品（不是 Dribble 模板）体现了类似的主语言？

### FORGE 案例回答

1. **主叙事**：Web3 项目从混乱探索逐步协同成型的过程（不是"我们投资 Web3"）
2. **时间维度**：顶部混沌字符场 → 滚动 → 字符收敛成网络节点 → 底部完整拓扑；与此同时文字内容从大标语 → 具体能力
3. **通道分工**：
   - 动效：chaos→order 5 维度演化
   - 字体：Grotesk 品牌 + Serif 机构感正文 + Mono 极客标签
   - 布局：段落错位（书籍感）+ 左右段落水平覆盖（叙事连续性）
   - 背景：ASCII 拓扑图（主叙事的主要视觉载体）
   - 颜色：黑 + 橙红 + 灰白（克制，不靠颜色装饰）
   - 文案：builder 气质，无 marketing 词
   - 细节：四角 FORGE serif 字母 0.1 opacity
4. **不做什么**：
   - 不做 3D WebGL 场景（太重，偏离 Web3 builder 气质）
   - 不做 glitch 赛博朋克（Dark.fi 反面）
   - 不做 flowchart 布局（YZi Labs 反面，已被领导否决）
   - 不做大字 hero + 栅格卡片（PPT 感俗套）
5. **参考锚点**：Dragonfly（主要，95% 气质对齐）+ Paradigm（局部：serif/mono 混搭）+ Base Ecosystem（局部：filter + card grid）

==这 5 个回答必须写进 `knowledge/design-docs/DESIGN-CONTEXT.md` 或单独的 `DESIGN-LANGUAGE.md`==。

## 主语言缺席的典型症状

项目出现以下症状之一，就是没有主语言：

- **"感觉差点意思"**：每个 section 都过关但合起来没有冲击力
- **每次改动都在做局部决策**：没有全局约束来指导"这里应该大一点还是小一点"
- **参考案例用得太多**：发现每个 section 学的是不同的参考站
- **动效东拼西凑**：hero 有 hover 效果 / about 有 fade in / features 有 scroll parallax / cta 有 shake —— 没有任何一条贯穿
- **用户给不出"高级感"的具体方向**：因为连用户自己都没法从混乱中分辨哪里是"核心"

## 如何在第一天提炼出主语言

### Step 1: 先做参考调研（8-12 个真实站）

见 [[AI前端设计认知框架]] 的调研层。关键是==必须真的用浏览器打开==，不是只看截图。

### Step 2: 做动效采访（这步极其关键）

见 [[AI 前端动效盲区与采访补偿]]。

### Step 3: 归纳共性 + 差异化定位

从调研结果里归纳：

- 这 8-12 个案例有什么==共性的东西==？（这往往就是当前品类的基础语言）
- 最打动我的==差异化的东西==是什么？（这是主语言的差异点）
- 我要延续哪些共性？要在哪个维度做差异化？

### Step 4: 用 5 个验证问题自检

回答不出来就继续调研或追问。不要跳到实现。

### Step 5: 写成 `DESIGN-LANGUAGE.md` 锁定

写进项目 `knowledge/design-docs/`。==每个后续的前端决策都必须能被这份文档解释==。

## 主语言 vs 审美的层级关系

```
审美（隐性认知）
  ↓ 追问解压
主语言（一句话主叙事 + 通道分工 + 不做什么）
  ↓ 通道拆解
每个元素的具体参数（字号 px / 动效 ms / 颜色 hex）
  ↓ 实现
代码
```

审美是最上游的隐性输入，主语言是第一层显性化产物，具体参数是第二层显性化产物。==没有主语言，参数就没有根==，每次改动都在局部凭感觉。

## 要抵抗的诱惑

- ❌ "先把 hero 做出来看看" → 没有主语言就做 hero，hero 会永远改不完
- ❌ "主语言可以边做边调整" → 主语言一旦开工就会被现状锁死，改主语言等于推翻重做
- ❌ "visual thesis 就是主语言" → 不是。visual thesis 是气质标签，主语言是叙事动线
- ❌ "用户的感觉就是主语言" → 用户的感觉是隐性输入，需要通过追问提炼成主语言
- ❌ "参考 Dragonfly 就够了" → Dragonfly 的气质可以参考，但主语言必须自己的叙事
