# 从参考案例复刻高级感：量化工作流

## 在体系中的位置（2026-04-21 补）

本笔记是 [[六维：形色字构质动是网站试吃的机械骨架]] 中==前五维（形、色、字、构、质）的执行手段==。六维骨架定义"要观察什么"，本笔记提供"DOM 层具体量化脚本"，形成**上位骨架 + 具体方法论**的挂接关系：

| 维 | 本笔记对应段 |
|---|---|
| **形** | Step 2 的 border-radius / SVG 路径采样 + Step 3 的元素轮廓记录 |
| **色** | Step 2.C 颜色层测量脚本 |
| **字** | Step 2.A 文本层测量脚本 |
| **构** | Step 2.B 布局层 + Step 2.D 间距层测量脚本 |
| **质** | Step 2.E 背景材质 + 阴影 + 渐变采样（2026-04-21 扩展） |

动维的量化不在本笔记，走 [[AI 前端动效盲区与采访补偿]]。

在 [[AI前端设计认知框架]] 的新阶段化流程里，本笔记活跃在==阶段 2（试吃六维）==的执行层。

## 一句话

高级感不是单一维度，不能用"空 vs 不空"概括，必须==从具体参考站逐项量化出来==才能被复现。"复刻" ≠ "抄布局"，是==打开浏览器插件、逐元素读 DOM、逐指标记录==的结构化过程。

## 为什么"看起来像"不够

AI 做前端最常见的翻车模式：

1. 用户给一个 URL："学这个"
2. AI 看了截图 + 读了 HTML 结构
3. 生成的代码"看起来像"，但气质全错
4. 用户："不对"
5. AI 继续猜
6. 循环

根因：==截图和 HTML 抓不到的信息太多==：

- 字号的实际像素值（截图看不准）
- 字重（看起来都是 light 但可能是 300 vs 400）
- 行高 / letter-spacing（微小差异决定节奏）
- 实际配色的 hex（截图 JPEG 压缩会偏色）
- 动效的时序 / ease curve
- 栅格的实际 px 单位（视觉上判断不准）
- padding / margin 的精确值
- 交互的触发范围和反馈

这些信息==不读 DOM 永远得不到==。想复刻高级感，必须做量化测量。

## 标准工作流

### Step 0：目标确认

在打开浏览器之前，明确：

- **要复刻什么**：整体气质？某个 section？某个交互？某个动效？
- **不复刻什么**：哪些是参考站特定的、不应该带到自己项目的？
- **与自己主语言的关系**：这份复刻服务于自己项目的主语言吗？（见 [[主语言是设计的第一原则]]）

### Step 1：打开参考站（浏览器插件）

工具选择：

- `claude-in-chrome` 插件：适合交互 + 读 DOM
- `chrome-devtools-mcp`：适合深度 inspector 类操作
- `firecrawl`：静态内容抓取，没有 DOM 交互
- Wayback Machine：原站下线时的 fallback

**陷阱**：参考站可能下线或改版。

> **本轮踩的坑**：Dragonfly 官网在复刻时正好在做 "2.0 Coming Soon" construction 重构，只剩一个 hero。Wayback Machine 2024 年的存档卡在 `LOADING_0%`（因为静态资源没抓到）。最终只能依赖用户先前手动截的 ABOUT 段截图。**启示**：重要参考站先抓一套本地快照（`references/` 目录），不要依赖"需要的时候再打开"。

### Step 2：分层量化测量

打开参考站后，按下面的清单==逐元素读 DOM==：

#### A. 文本层（对应六维之【字】）——每个关键文本元素都测一遍

```javascript
(() => {
  const el = document.querySelector('...'); // 用 devtools 定位
  const cs = getComputedStyle(el);
  return {
    // 字体基础
    fontFamily: cs.fontFamily,
    fontSize: cs.fontSize,          // px 值
    fontWeight: cs.fontWeight,      // 数字，不是 bold/normal
    lineHeight: cs.lineHeight,      // 具体 px
    letterSpacing: cs.letterSpacing,
    // 颜色
    color: cs.color,                 // rgb() 或 oklab()
    // 对齐
    textAlign: cs.textAlign,
    // 装饰
    textTransform: cs.textTransform, // uppercase?
    fontStyle: cs.fontStyle,         // italic?
  };
})()
```

记录样本：

```
Dragonfly ABOUT 段 paragraph:
- fontFamily: "Martina Plantijn", serif
- fontSize: 32px
- fontWeight: 400
- lineHeight: 44px (1.375)
- letterSpacing: 0px
- color: rgb(242, 242, 242)
```

#### B. 布局层（对应六维之【构】）——每个 section 的容器

```javascript
(() => {
  const sec = document.querySelector('section');
  const rect = sec.getBoundingClientRect();
  const cs = getComputedStyle(sec);
  return {
    width: rect.width,
    viewportRatio: (rect.width / window.innerWidth * 100).toFixed(1) + '%',
    maxWidth: cs.maxWidth,
    padding: cs.padding,
    margin: cs.margin,
    // 相对视口位置
    leftFromViewport: (rect.left / window.innerWidth * 100).toFixed(1) + '%',
  };
})()
```

记录样本：

```
Dragonfly ABOUT section:
- width: 1320px
- viewportRatio: 82.5%
- maxWidth: 1320px
- padding: 100px 60px
- leftFromViewport: 8.75% (居中)
```

#### C. 颜色层（对应六维之【色】）——背景、文字、边框、强调

```javascript
(() => {
  const body = document.body;
  const accent = document.querySelector('.accent'); // 定位具体元素
  return {
    bodyBg: getComputedStyle(body).backgroundColor,
    bodyFg: getComputedStyle(body).color,
    accent: accent ? getComputedStyle(accent).color : null,
  };
})()
```

记录样本：

```
Dragonfly:
- bodyBg: rgb(0, 0, 0)
- bodyFg: rgb(242, 242, 242)
- accent: rgb(250, 76, 20)  # #FA4C14
```

#### D. 间距层（对应六维之【构】）——section 之间、元素之间、留白关系

```javascript
// 测量相邻元素之间的 gap
(() => {
  const a = document.querySelector('...');
  const b = document.querySelector('...');
  return {
    verticalGap: b.getBoundingClientRect().top - a.getBoundingClientRect().bottom,
    horizontalGap: b.getBoundingClientRect().left - a.getBoundingClientRect().right,
  };
})()
```

重点记录：

- Hero → 第一个内容 section 的间距
- 相邻段落之间的间距
- 标题 → 正文之间的间距
- 元素 → 分隔线之间的间距

#### E. 材质层（对应六维之【质】）——背景、噪点、阴影、渐变、透明度（2026-04-21 新增）

```javascript
(() => {
  const el = document.querySelector('.hero');  // 具体元素
  const cs = getComputedStyle(el);
  return {
    // 背景层
    background: cs.background,
    backgroundImage: cs.backgroundImage,  // gradient / noise / texture
    backgroundBlendMode: cs.backgroundBlendMode,
    // 滤镜与模糊
    filter: cs.filter,
    backdropFilter: cs.backdropFilter,
    // 阴影与发光
    boxShadow: cs.boxShadow,
    textShadow: cs.textShadow,
    // 透明度
    opacity: cs.opacity,
    // 边界质感
    borderRadius: cs.borderRadius,  // 也对应形维
    borderStyle: cs.borderStyle,
  };
})()
```

重点观察：

- **噪点**：有没有 noise texture？density？blend mode？
- **渐变**：conic / linear / radial？几个颜色停靠点？
- **阴影**：多层叠加？硬边还是软边？颜色饱和度？
- **玻璃感**：backdrop-filter blur？saturate？
- **真实材质**：纸质 / 金属 / 反光用图案还是 CSS？

#### F. 形状层（对应六维之【形】）——图标族 / 装饰元素 / 分割线（2026-04-21 新增）

不能完全靠 DOM 量化，需要**截图 + 标注**的方式：

- **图标族风格**：线性 / 填充 / 几何 / 手绘？一套风格还是混用？
- **分割线**：硬线 / 虚线 / 渐隐？thickness？
- **装饰符号**：heraldic / geometric / organic？出现频率？
- **`border-radius` 取值族**：整站的圆角风格是锐利 / 柔和 / 完全圆？
- **SVG 路径复杂度**：简洁线条还是复杂插画？

推荐做法：==一张标注截图==，把以上要素用注释框圈出来 + 一段文字描述风格倾向。

#### G. 动效层（对应六维之【动】）——时序、ease、触发、双向性

见 [[AI 前端动效盲区与采访补偿]] 的反向采访流程：

- 用浏览器插件滚动 + 多次截图
- 记录每个滚动位置的关键元素状态
- 问用户求证
- 写成量化语法

### Step 3：归档为"参考量化表"

一个参考站的量化结果==必须写成一张表==，便于后续查阅：

```markdown
# Dragonfly.xyz ABOUT 段量化表

| 维度 | 测量值 | 备注 |
|---|---|---|
| 容器宽 | 1320px (82.5% vw) | 不顶到视口边 |
| 容器 padding | 100px 60px | |
| 段 1 字号 | 32px | serif |
| 段 1 fontFamily | Martina Plantijn, serif | |
| 段 1 line-height | 44px (1.375) | |
| 段 1 color | #F2F2F2 | |
| 段间距 | 60px | |
| 段 2 ml offset | 240px (约 18%) | |
| accent color | #FA4C14 | |
```

这张表==可以直接被 AI 用来生成 Tailwind 代码==。

### Step 4：映射到自己项目

测量完参考站，==不要直接抄==。要考虑：

- 自己项目的视口宽度（参考站是 1600 vw？1920？）
- 自己项目的主语言一致性（这些参数是否服务于我的主叙事？）
- 哪些参数保留、哪些按比例换算、哪些重新决定

**换算方法**：

```
参考站宽度：1600px
自己项目视口：1728px
比例：1.08

参考站字号：32px
自己项目对应：32 × 1.08 ≈ 34.5 → 取 34 或 36
```

但很多参数==不适合按比例换算==（字号有节奏感、颜色是 hex 等价的），需要具体判断。

### Step 5：实现后再回参考站对位

AI 实现第一版后，==要求用户把第一版和参考站同屏对比==：

- 并排截图
- 框出差异点
- 用户给定性反馈 → AI 追问定位 → 量化差异 → 改

这个对位过程本质上也是 [[审美是隐性认知，追问是唯一的解压工具]] 的追问循环。

## 参考案例的选择原则

不是找得越多越好。==质 > 量==。

### 好参考的特征

- **主语言清晰**：你能一句话说出它在讲什么故事
- **同品类**：和你要做的东西在同一个场景（不要拿游戏网站参考 B2B SaaS）
- **量级相称**：同等复杂度（不要拿 Apple 参考小工作室站）
- **可测量**：真实活站，可以打开浏览器 DOM 读
- **有特色细节**：有至少一个独特做法值得学

### 坏参考的特征

- Dribble / Behance 设计稿：只能看截图，读不了 DOM，不知道实际 px
- 纯模板站：没有主语言，是俗套的集合
- 完全不同品类：气质无法迁移
- 已下线或改版：不可测量

### 数量建议

- **8-12 个**：初始调研阶段的搜索量
- **3-5 个精品**：实际深度量化的对象
- **1-2 个主参考**：整体气质复刻来源（本项目 Dragonfly）
- **2-3 个局部参考**：某个细节学习来源（Paradigm 的 mono label / Base 的 filter pill）

> **陷阱**：太多参考会稀释主语言。如果每个 section 的参考都不一样，最后会拼贴。==主参考最多 1-2 个==。

## 测量脚本：通用工具

把下面这段存成 `scripts/reference-profiler.js`，粘贴到任何参考站的浏览器 console 就能跑：

```javascript
(() => {
  // 使用方法：
  // 1. 在目标站点打开 devtools console
  // 2. 粘贴并运行
  // 3. 在提示符输入 CSS 选择器
  // 4. 得到量化数据
  
  const sel = prompt('CSS selector?');
  const el = document.querySelector(sel);
  if (!el) return '未找到元素';
  
  const cs = getComputedStyle(el);
  const rect = el.getBoundingClientRect();
  
  return {
    element: el.tagName + (el.className ? '.' + el.className.split(' ')[0] : ''),
    box: {
      width: Math.round(rect.width) + 'px',
      height: Math.round(rect.height) + 'px',
      widthVw: (rect.width / window.innerWidth * 100).toFixed(1) + '%',
      leftVw: (rect.left / window.innerWidth * 100).toFixed(1) + '%',
    },
    text: {
      family: cs.fontFamily,
      size: cs.fontSize,
      weight: cs.fontWeight,
      lineHeight: cs.lineHeight,
      letterSpacing: cs.letterSpacing,
      color: cs.color,
      align: cs.textAlign,
      transform: cs.textTransform,
      style: cs.fontStyle,
    },
    space: {
      padding: cs.padding,
      margin: cs.margin,
    },
    bg: cs.backgroundColor,
    border: cs.border,
  };
})()
```

## FORGE 案例：本轮量化实战

### 第一次参考 Dragonfly 失败的原因

初期 AI 只看了用户提供的 Dragonfly Hero 截图，==没有做 DOM 量化==，凭"看起来像"生成了：

- 字号：`clamp(64px, 10vw, 120px)` —— 大致对
- 字体：Space Grotesk —— 不对（Dragonfly 是 Serif 混搭）
- 背景：随机 ASCII 散布 —— 错（应该是结构化网络拓扑或世界地图）
- 颜色：#0A0A0A 背景 —— 错（应该是纯 #000）
- 品牌色：自选的 —— 后来发现和 Dragonfly 的 #FA4C14 完全一致，但不是用量化得到的

### 后期补做量化才修正

几轮迭代后，用户明确反馈 "对齐 Dragonfly"，我才打开 Wayback 测量具体：

- 背景色改为 #000 纯黑
- 品牌色用 #FA4C14 明确（原来是自选的碰巧对）
- 引入 Cormorant Garamond serif 做 tagline
- ASCII 背景改成结构化网络拓扑
- 段落布局用 serif 错位（Dragonfly ABOUT 同构）

### 教训

==早期把 DOM 量化做扎实，可以省掉 5-6 轮返工==。量化阶段看起来慢（需要逐元素测量），但每一个量化点都==消除一次未来争议==。

## 工具陷阱清单（本轮踩过的）

- **chrome-in-claude 截图对 Framer Motion MotionValue 元素会拍黑屏**：解决方法是放弃截图，用 `getBoundingClientRect + getComputedStyle` 当证据
- **Lenis 劫持 window.scrollTo**：JS 方式滚动不触发 Framer Motion `useScroll`。必须用真实 wheel events
- **Wayback Machine 的静态资源抓取不完整**：`LOADING_0%` 卡死。Fallback 是用户本地手动截图
- **`max-w-[X%]` ≠ `w-[X%]`**：max-w 下 box 会被内容收缩；要强制填满应该用 w-[X%]
- **text-justify 在 span-per-word 架构下**：空格必须放 span 外部，否则无法拉伸词间距

这些陷阱==必须写进项目的 `references/tools-gotchas.md`==，下次再用同一套工具时就不用重新踩。

## 要抵抗的诱惑

- ❌ "看过几个参考站大概知道怎么做" → 没量化的"看过"等于没看
- ❌ "直接让 AI 爬参考站代码" → 代码是实现，主语言的参数很多藏在 computed style 里，HTML/CSS 源码看不出
- ❌ "量化太麻烦，先做再说" → 早量化 1 小时，省 5 轮返工
- ❌ "参考站的数据可以之后再测" → 参考站会下线、会改版，要做本地快照
- ❌ "多找几个参考求稳妥" → 参考过多会稀释主语言
