# 深度采访双轮：产品设计师视角的横切机制

## 一句话

==前端设计不是先做 UI，是先当用户的产品设计师==——Agent 必须主动用引导式提问把用户脑子里隐性的"架构 + 文案"采访出来，分前后两轮触发，前轮建目标、后轮拔细节。

## 为什么需要"产品设计师视角"而不只是"设计师视角"

前端 AI 常见误区：收到"做个官网"的需求就直接进设计——定主语言、调研参考、生成代码。结果发现做完后**整体架构不对**（page 层级错、功能分布错）或**文案假大空**（像 GPT 生成的营销话术）。

根因：==设计师视角只解决"长什么样"==，不解决"**讲什么 + 怎么组织**"。展示型网站的核心价值在产品内容和叙事推进，这属于产品设计师的工作。

AI 必须同时扮演两个角色：

| 角色 | 职责 | 对应机制 |
|---|---|---|
| 前端设计师 | 六维拆解 + 视觉生成 + 代码实现 | 试吃 + 三件套 + 代码 |
| **产品设计师** | 架构拆解 + 文案采访 + 叙事设计 | **深度采访（本笔记）** |

## 为什么是双轮

单轮采访（只在需求阶段问一次 / 只在试吃后问一次）都不够：

- **只问需求阶段**：此时用户没有视觉参考，很难说清"我要什么架构、什么调性的文案"
- **只问试吃后**：目标已跑偏，事后补救代价大

双轮的分工：

| 轮次 | 触发时机 | 目标 | 提问重点 |
|---|---|---|---|
| **前轮** | 需求三件套阶段——开工前 | 建立目标边界 | 产品是什么 / 用户是谁 / 成功信号 / 反向——不想变成什么 |
| **后轮** | 试吃 + Moodboard 选定后，design.md 定稿前 | 结合视觉参考拔细节 | 页面结构 / section 排布 / 文案调性 / 交互路径 / 转化路径 |

后轮是==关键差异化==：很多 AI 流程直接在前轮采完就开工，跳过后轮。但视觉方向确定后，"同一段文案在不同调性下该怎么写"、"同一个 CTA 在当前 moodboard 下该用什么动词"这些细节必须在后轮拔出来。

## 前轮：需求阶段的五类提问

前轮的五类引导式提问（参考 [[审美是隐性认知，追问是唯一的解压工具]] 的追问哲学）：

| 类       | 提问模板                                        | 为什么问                  |
| ------- | ------------------------------------------- | --------------------- |
| **定位类** | "这个产品在一句话内告诉陌生人，你会怎么说？"、"三个月后这个站成功了，你怎么知道？" | 避免 Agent 接手时对产品没有清晰定位 |
| **用户类** | "谁会来看这个站？他们之前在看什么？离开这个站要去哪里？"               | 建立 user journey 语境    |
| **反向类** | "你不想变成什么样？哪些竞品的样子让你觉得反感？"                   | 反例比正例信息密度高            |
| **资源类** | "这个站要支持多少个页面？有没有真实文案或者需要我也帮你生成？"            | 建立规模预算                |
| **时间类** | "这个站什么时候要上线？是一次性交付还是持续迭代？"                  | 影响 scope 控制           |

前轮输出：==产品边界定义（写进 `design.md` §1 目标层）==。

## 后轮：视觉定稿前的五类提问

后轮触发条件：试吃完 4-5 站 + Moodboard 选定 + 初步 design.md 草稿 → **此时必须再问一次**，不能直接进入生成阶段。

| 类 | 提问模板 | 为什么问 |
|---|---|---|
| **架构类** | "首页要不要导航栏？有几级？信息架构是 SPA 还是多页？各页目标是什么？" | AI 默认走最 generic 的 landing 八股，必须逐层确认 |
| **section 类** | "首页从上到下有 X 个 section 我列出来，你看哪个要加、删、调顺序？" | 把"首页叙事"从黑箱变成可选择题 |
| **文案调性类** | "现在 Moodboard 是 X 风格，对应文案应该是 A 学院派 / B 口语化 / C 诗意化，你倾向哪个？给个参考句。" | 文案调性必须和视觉调性对齐，不能自顾自写 |
| **交互路径类** | "用户第一眼看 hero 后，你希望他的下一个动作是什么？往下滑？点 CTA？看 demo 视频？" | 确定转化路径 |
| **反向细节类** | "Moodboard 里的 X 元素你会担心用户看不懂吗？Y 动效会不会太花？" | 用户看到具体视觉后才能识别的担忧，必须在后轮捕捉 |

后轮输出：==架构定稿 + 文案方向 + 交互路径==（写进 `design.md` §2-5 + §9 Agent Prompt Guide）。

## 和"审美追问"（三段式）的区别

双轮深度采访和 [[审美是隐性认知，追问是唯一的解压工具]] 的三段式追问是**姊妹机制但触发阶段不同**：

| 机制 | 阶段 | 目的 | 隐性来源 |
|---|---|---|---|
| **深度采访双轮** | 前置建立——代码之前 | **建立**目标 / 架构 / 文案的边界 | 用户脑子里的产品愿景 |
| **审美追问三段式** | 后置纠偏——代码之后 | **纠正**"感觉不对"的评审反馈 | 用户看完代码后才涌现的审美直觉 |

两者正交——深度采访管**出发前的定向**，审美追问管**出发后的纠偏**。都依赖"**用户脑子里有隐性认知，Agent 必须主动问**"这个共同前提。

## 横切机制的时序位置

在 [[AI前端设计认知框架]] 的阶段化流程里：

```
需求三件套 [★ 前轮深度采访]
     ↓
试吃六维 × 4-5 站
     ↓
Moodboard 生成 + 选定
     ↓
[★ 后轮深度采访]
     ↓
design.md 定稿
     ↓
示意图 + 动效帧序列 → 代码
```

两个 ★ 是深度采访的必触发点，==跳过任何一个都会在代码层付出额外迭代成本==。

## Agent 执行规范

当 Agent 触达深度采访阶段时必须：

1. **显式宣告角色切换**：从"前端设计师"切到"产品设计师"，让用户知道这轮不是聊视觉
2. **一次问 3-5 个，不一次性甩 20 个**：采访是互动，不是 checklist；按用户回答追问
3. **选择题优先，开放题兜底**：用户画像是 vibe coder，选择题降低回答负担（参考 [[审美是隐性认知，追问是唯一的解压工具]] 的选择题化原则）
4. **产出物写回 design.md**：采访结果必须落回 `design.md` 对应段落，不能只留在对话里

## 常见反模式

- ==跳过前轮直接试吃==：看参考站前先定位；没目标的试吃会把任何漂亮站都评高分
- ==跳过后轮直接生成代码==：最常见的失败模式；Moodboard 选定后立刻写代码，文案调性和视觉脱节
- ==把深度采访做成问卷==：20 题一次性甩给用户，用户答不动；一定要分批追问
- ==采访完不回写 design.md==：采访结果只留在对话里，下次新 session 丢失
