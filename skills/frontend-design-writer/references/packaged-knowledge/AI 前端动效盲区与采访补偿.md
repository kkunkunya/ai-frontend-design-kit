# AI 前端动效盲区与采访补偿

## 在体系中的位置（2026-04-21 补）

本笔记是 [[六维：形色字构质动是网站试吃的机械骨架]] 中==第六维"动"==的执行手段——六维骨架定位"需要采访什么"，本笔记提供"采访的五类问题 + 量化语法"，形成**上位骨架 + 具体方法论**的挂接关系。

采访输出的量化语法是**宏观层**描述，代码实现阶段需要进一步升级到**微观实现 prompt**（逐组件代码级规格）——详见 [[动效文档两层：MOTION-SPEC vs 实现 prompt 集]]。

在 [[AI前端设计认知框架]] 的新阶段化流程里，动效采访活跃在：

- **阶段 2（试吃六维）** 的动维观察
- **阶段 4C（动效帧序列）** 的前置输入
- **阶段 6（代码实现）** 的微观 prompt 生成依据

## 一句话

AI 永远看不到动效的时间维度——==截图是空间快照，动效是时间曲线==，两者在物理上不兼容。唯一的补偿机制是：==把用户脑子里的隐性交互感受，通过结构化追问转成显性的量化描述==。

## 为什么这是一个独立问题

前端里的其它东西——颜色、字体、布局、间距——AI 都能从截图直接读出来。唯独==动效活在帧与帧之间的时间里==，一张截图最多捕获某个瞬间状态，捕获不了：

- **节奏**：什么快、什么慢、什么在等什么
- **触发关系**：谁是因、谁是果、中间隔多久
- **回放行为**：只播一次还是往回滑会逆放
- **阻尼与惯性**：是平滑还是弹性还是硬切
- **层级叠加**：多个动效同时发生时谁压谁、怎么叠

过去我们把这些统统塞进 "interaction & motion" 一段话里糊过去，实际每个项目都在这一层反复翻车。

## 动效盲区的三个结构性后果

### 后果 1：AI 必然生成"半成品动效"

就算参考案例的 URL 给全了，让 AI "参考 Dragonfly 的滚动体验做一套"，它最多能复刻：

- 颜色 ✓
- 字体 ✓
- 大致布局 ✓
- 动效：==只会生成它从训练数据里记得的通用模式==，比如 `whileInView` + `once: true` 单次触发

至于用户真正感受到的"自上而下主叙事"、"逐字 blur 揭示"、"双向连续回放"、"背景跟随主文字的呼吸"——==模型无法从截图感知到==，只能瞎猜。

### 后果 2：用户无法一次说清"感觉不对"

当用户看到第一版动效说"不对"，他==自己也不一定能立刻说出来哪里不对==。因为：

- 他感受到的是**时间上的节奏不对**，但没有词汇描述时间
- 他的标尺在参考站上，但他不会主动去对参考站一帧帧看
- 他的审美判断是隐性的（见 [[审美是隐性认知，追问是唯一的解压工具]]），他只知道"就是不对"

结果是：用户返一句"不对"，AI 再瞎调一版，还是不对。==反复几次后用户累了，说"算了就这样吧"==，项目带着错误动效上线。

### 后果 3：上下文短 → 动效细节快速遗忘

前端项目做完后一周，用户自己都记不清最初是为什么选了某个动效时序。AI 的上下文窗口更短——一次对话结束后，所有调参细节全部丢失。

这意味着：**动效细节必须在用户还有记忆时立即被采访、立即被显性化**，否则这笔隐性知识永远丢了。

## 采访补偿协议

### 何时必须触发采访

| 时机 | 触发条件 | 动作 |
|---|---|---|
| **调研后**（参考截图完） | 还没动手写代码 | 对用户做"参考站动效采访"：让用户真的滚动一次、hover 一次、点击一次，一边操作一边被问 |
| **第一版实现后** | 用户看完说"不对" | 对用户做"差距采访"：让用户指出哪一段感觉不对，和参考站的哪里不一样 |
| **项目阶段收尾时** | 还没关闭对话前 | 对用户做"动效汇总采访"：把所有调过的动效细节一次性采访出来沉淀到文档 |

关键原则：==不要等用户主动描述动效。用户不会。AI 必须主动问==。

### 问题模板：五大类

不管是参考站采访还是差距采访，问题都围绕这 5 类：

#### 1. 节奏类（时间与速度）

- 整个动效从开始到结束大约多久？（秒 / 毫秒）
- 是匀速、加速还是减速？
- 有没有中途停顿？停多久？
- 多个元素是同时开始还是有先后？先后间隔大约多久？

#### 2. 触发类（因果关系）

- 这个动效是什么触发的？（滚动位置 / hover / 点击 / 自动加载 / 鼠标位置）
- 触发点是滚动到第几屏、第几像素？
- 触发后会不会再次触发？还是只触发一次？
- 触发是硬的还是软的？（瞬间 vs 渐进）

#### 3. 双向性类 ⭐（最容易被忽略的一类）

- 滚到看到这个动效，然后滚回去，它会逆向播放吗？还是定住？
- 如果逆向播放，速度和正向一样吗？
- 用户在任意滚动位置停住，画面状态是唯一确定的吗？还是取决于怎么来的？

> **硬约束**：展示型网页的核心动效默认应双向连续——跟随 scrollY 位置实时变化。单次触发（`whileInView` + `once: true`）仅限非关键装饰元素。

#### 4. 层级类（多动效共存）

- 这个动效发生时，背景有在变吗？
- 前景元素之间有先后顺序吗？
- 动效之间有没有"谁压谁"的层级？

#### 5. 反例类（什么不要）

- 有没有看过做得特别糟的类似动效？糟在哪？
- 这个动效==不应该==像什么？
- 有没有边界——做过头了反而不对？

### 采访输出的量化语法

采访出来的感受要立即转成==可执行的量化描述==，格式固定：

```
[触发条件] → [主体] → [变化] → [时序/范围]
```

**示例（来自 FORGE 项目）**：

```
✗ 模糊描述："滚下去时标题淡出"
✓ 量化描述：
  - 触发：scrollY 0 → viewport_height × 0.6
  - 主体：Hero h1 "FORGE" 五个字母
  - 变化：opacity 1 → 0，每个字母按 CHAR_DELAYS 独立 stagger
         blur 0px → 12px
         y offset 0 → -80px
  - 时序：字母 0 在 progress 0.08 起，字母 4 在 0.23 起
  - 双向：progress 归 0 时完全逆放
  - 反例：禁止 `whileInView once: true`
```

这种描述==可以直接翻译成 Framer Motion / CSS 代码==，不需要猜。

### 量化语法的升级路径：动效实现 prompt 集（2026-04-21 补）

上面的量化语法是**宏观层**（给人读 + 记录决策依据）。进入代码实现阶段时，核心动效组件需要升级到==微观层==——一份**完整的实现 prompt**，覆盖 theme tokens / 字体引用 / 组件签名 / 逐元素 Tailwind class + framer motion 字段 / 父组件行为 / 时序总表。

详见 [[动效文档两层：MOTION-SPEC vs 实现 prompt 集]]。实现 prompt 按 LoadingScreen 风格写，==直接喂给 Agent 写代码==，不留歧义空间。

每个核心动效组件一份 prompt，住在项目 `knowledge/design-docs/motion-prompts/<component>.md`。

## 反向采访：AI 主动过一遍参考站

当用户自己说不清楚、或者没时间一帧帧讲解时，AI 可以主动做"反向采访"：

1. **用浏览器插件连接参考站**（claude-in-chrome / chrome-devtools-mcp）
2. **主动滚动 + 截图** 捕获 5-10 个状态快照（每 10-20% 滚动一次）
3. **DOM 读取** 关键元素的 scroll-driven 样式（`getComputedStyle` 在不同滚动位置的 diff）
4. **向用户求证**：
   - "我看到滚到 30% 时 hero 标题 opacity 变成 0.4 了，这是预期的吗？"
   - "滚回顶部时标题会恢复吗？"
   - "背景粒子在你滚动时有同步变化吗？"
5. **填入问题模板**：把观察结果转成问题清单，让用户逐条确认

这是==部分补偿==动效盲区——AI 通过滚动和多次截图，人工拼出时间维度。不完美，但比纯截图强很多。

> **工具陷阱**（本轮踩过的）：
> - `chrome-in-claude` 的截图工具对 Framer Motion `style={{motionValue}}` 驱动的元素会拍黑屏。解决：改用 `getBoundingClientRect + getComputedStyle` 读 DOM 数据当证据，不依赖截图。
> - Lenis 平滑滚动会劫持 `window.scrollTo()`，JS 方式滚动不触发 Framer Motion `useScroll` 更新。必须用真实 wheel 事件（`computer.scroll`）。

## 做完立即复盘采访

项目进入收尾阶段——动效已经调到用户满意了——==这时必须立即做一次"汇总采访"==，否则：

1. 下次对话上下文丢失，AI 不知道为什么当初这么调
2. 用户自己一周后也忘了
3. 任何后续迭代都会重新踩同样的坑

**汇总采访清单**（项目收尾时必问）：

| 类别 | 问题 |
|---|---|
| **主语言** | 整个项目的主叙事是什么？（见 [[主语言是设计的第一原则]]） |
| **关键动效清单** | 有几个核心动效？各自负责表达什么？ |
| **时序参数** | 关键动效的 duration / delay / ease 是多少？为什么是这些值？ |
| **触发范围** | 每个动效的 scroll 范围、hover 区域、触发阈值 |
| **双向性** | 哪些是双向连续的？哪些是一次性的？为什么这样切？ |
| **反模式记录** | 这次踩过哪些坑？下次要避免什么？ |
| **参考链** | 这个动效从哪个参考站学的？参考了哪些具体细节？ |

输出到项目的 `knowledge/design-docs/` 下的 motion 专题文档。这份文档是==未来跨项目复用的唯一可靠上下文==。

## FORGE 项目案例复盘

### 本轮的动效调整次数（约 10 轮调动效的触发复盘）

| 轮次 | 用户反馈（定性） | 量化翻译（AI 的活） | 结果 |
|---|---|---|---|
| 1 | "动效要双向连续" | 禁用 `whileInView once:true`，所有动效绑 `scrollYProgress` | ✓ |
| 2 | "背景没有主语言" | chaos→order 5 维度：抖动 / 字符池 / 密度 / 完整度 / 显现 | ✓ |
| 3 | "布局太松散" | DOM 实测 → 段落总高从 1359 → 969 (−29%)，容器 896→768 | ✓ |
| 4 | "字号太小" | +10px 一轮（26→36），再 +8px 一轮（36→44） | ✓ |
| 5 | "两边太空" | Dragonfly 风格：ml-auto + text-right 推到右边 | ✓ |
| 6 | "不要靠拉间距顶边" | 撤销 text-justify，改 text-right 自然对齐 | ✓ |
| 7 | "底下 CONNECT 太暗" | 根因：3 个 pillar 各自 stagger 导致某时刻仅 0.7 opacity。合并共享 motion value | ✓ |

**复盘要点**：

1. 如果项目开始就先做动效采访，1、2 轮就能一次性说清"chaos→order + 双向连续"，不用重来 7 次
2. 用户 5、6 两轮的反馈很微妙——他==不是反对 text-justify 的功能==，而是反对"拉间距顶边"这种**古怪感**。这是典型的隐性审美判断，必须追问才能挖出
3. 第 7 轮的 CONNECT 偏暗根因是 staggered scroll ranges，用户不可能直接说出根因。AI 必须==把"它比另外两个暗"翻译成 scroll progress 区间计算==才能定位

### 本项目的主语言（采访沉淀）

- **主叙事**：scroll-driven chaos → order（从混沌到有序的网络拓扑）
- **触发**：scrollY / (viewport × 1.2)，0 到 1
- **5 个表达维度**：
  - 位置抖动：节点 ±14px / 边 ±8px → 0
  - 字符池：`*#@%&+=?~{}[]<>` → 固定结构 `◆ ● ■ · | / \ - . :`
  - 环境密度/透明度：0.06-0.15 baseAlpha → 0.05 final
  - 连线完整度：30% → 100%
  - 节点层级显现：layer 0 → layer 3
- **锚点**：中心枢纽 `◆` 永远橙红、永远锁定字符、永远无抖动
- **双向**：全部双向连续，scroll 回归时逆放

这段话==必须在对话结束前写入项目 knowledge==，否则永远丢失。

## 最小实践清单

新前端项目启动时，按顺序做：

- [ ] 参考站 URL 收集完
- [ ] 让浏览器插件打开每个参考站
- [ ] **⭐ 停下来，做动效采访**：
  - [ ] 要求用户亲自在每个参考站滚动 + hover + 点击
  - [ ] 问 5 大类问题，记录量化语法
  - [ ] 特别确认"双向性"和"反例"
- [ ] 把采访结果写进项目 `knowledge/design-docs/DESIGN-CONTEXT.md` 的 interaction & motion 段
- [ ] 只有写完采访结果，才能开始写第一行代码
- [ ] 项目收尾前做一次"汇总采访"，沉淀到 `knowledge/design-docs/motion-spec.md`

## 要抵抗的诱惑

- ❌ "我看过 Dragonfly 了，应该能复刻" → 看过 ≠ 感受过动效
- ❌ "先做一版再让用户看" → 没有采访的第一版必然错
- ❌ "用户说不清就算了" → 说不清不是问题，不追问才是问题
- ❌ "这个动效参数先随便写" → 随便写的参数未来没人知道为什么
- ❌ "截图看起来就是这样" → 截图骗人
